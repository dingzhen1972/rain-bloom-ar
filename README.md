# 雨落成花 · Smile → Rain, Laugh → Fireworks (Web AR)

直播 / 自拍场景的网页 AR 互动：**微笑时屏幕开始下雨，大笑时雨被点燃、炸成烟花，烟花火花会落到你的头上和肩上并弹开。**
手机和电脑浏览器打开即用，不装 App，画面全部在本机处理，不上传。

- Live Demo：<https://dingzhen1972.github.io/rain-bloom-ar/>
- 实拍测试成片：[demo/clip1_ar.mp4](demo/clip1_ar.mp4)、[demo/clip2_ar.mp4](demo/clip2_ar.mp4)（表情由真实模型自动识别，非手动触发）

---

## 0. 体验流程

| 用户在做什么 | 识别到什么 | 画面 |
|---|---|---|
| 平静地看镜头 | 无表情 | 没有雨，提示「微笑一下，开始下雨」 |
| 微笑 | 相对自己平时的嘴型，嘴角上扬 | 雨下起来，越笑越大；雨有远近，落到头顶、肩膀会溅水花，身后的雨被人挡住 |
| 笑出声的一下「哈」 | 微笑中下颌明显张开一次 | 嘴边的雨亮一下，嘴边一团暖光 |
| 大笑 | 微笑 + 张嘴，持续 0.25 秒；或 1.6 秒内 3 声「哈」 | 火从嘴边一滴一滴传开，雨变成金色星屑上飘；身后天空连续放烟花，画面转黄昏色；最后一发金色瀑布在头顶炸开，火花**落到头和肩上弹起、滑落**，转头会把火花顶开 |
| 烟花结束（约 7.8 秒） | 冷却 1 秒 | 回到雨或晴，可以再笑一次 |

只微笑、只张嘴（说话、打哈欠、喊叫）都不会触发烟花。

## 1. 部署（三选一，均为纯静态，服务器成本为 0）

**GitHub Pages（推荐）**
1. 新建 **Public** 仓库，上传本文件夹全部内容（含隐藏的 `.github/`、`.nojekyll`）。
2. Settings → Pages → Source 选 **GitHub Actions**。
3. 推送到 `main`，等 **Deploy to GitHub Pages** 变绿，打开 <https://dingzhen1972.github.io/rain-bloom-ar/>。

部署时会自动运行 `scripts/fetch-vendor.sh`，把 MediaPipe 的 JS/WASM 和两个模型下载进站点自托管，用户端正常情况下不依赖 jsDelivr 和 Google Storage；运行时若自托管资源不可用，再依次尝试备用 CDN。

**Netlify / Vercel**：直接导入仓库，`netlify.toml` / `vercel.json` 已配好构建命令，并给模型和 WASM 设置一年缓存。

**自动验收**：每次推送还会跑 **Verify AR**。它在云端浏览器里用真实模型播放 `tests/fixtures/laugh.webm`，不做任何手动触发，检查四项：模型和人像分割是否加载、多数帧是否认出人脸、笑是否被自动识别并放出烟花、是否导出成片。报告、截图和导出视频在该次运行的 Artifacts → `ar-verify` 里。

## 2. 架构

```
摄像头 / 视频 ──► LaughDetector（MediaPipe FaceLandmarker + ImageSegmenter，按设备档位限频）
                     │  smile / jaw / 嘴的位置 / 脸框 / 人物上沿轮廓
                     ▼
               LaughController（个人基线 → 相对分数 → 「哈」/ 大笑 判定，冷却）
                     │  setMood / pulse / trigger
                     ▼
               ChainRainEffect（物理 + 绘制：深度雨、点燃、烟花、碰撞）◄── theme.js（全部视觉参数）
                     │
Governor（帧耗时 → 自动降/升档） ──► canvas 9:16 ──► 录制 / 导出（MediaRecorder）
```

| 文件 | 职责 | 改视觉时要动吗 |
|---|---|---|
| `src/theme.js` | 颜色、尺寸、数量、烟花编排、调色、提示文案 | **只改这里** |
| `src/effect-chain.js` | 深度雨、点燃、烟花与碰撞物理、绘制机制 | 只有换画法时 |
| `src/laugh.js` | 识别与笑声判定 | 否 |
| `src/perf.js` | 设备档位、自动降档 | 否 |
| `src/app.js` | 三种模式、竖屏构图、定格补完、录制 | 否 |
| `src/hud.js` | 提示与笑声计（读 theme.hud） | 否 |

## 3. 性能设计（ROI 优先）

| 手段 | 作用 |
|---|---|
| **设备分档**（`perf.js`）：根据 CPU 核数、内存、GPU 型号、是否手机分成高、中、低三档 | 画布 1080 / 720 / 540；识别 30 / 24 / 15 Hz；人像分割每 2 / 3 / 4 次识别跑一次；粒子预算 100% / 75% / 50%；低档锁 30 fps |
| **运行时调速器** | 帧耗时超预算 1 秒就降 15% 粒子；连续 6 秒有余量才慢慢升回，不会来回抖 |
| **识别调度** | 只在视频出新帧时识别；识别耗时超过间隔的 60% 就自动拉长间隔（最低 8 Hz），识别永远不吃掉渲染预算 |
| **模型按需加载** | 点「开始」才下载人脸与人像模型；只打开首页的访客不下载模型。Netlify/Vercel 配置一年缓存，GitHub Pages 使用平台默认缓存 |
| **零整屏中间层** | 「人前 / 人后」遮挡用解析法逐点判断（点与轮廓比较），不用 canvas 裁剪和离屏整屏图层 |
| **单次调色** | 色调、天空压暗、暗角合成一张 1/4 分辨率的乘法贴图，按 16 档缓存；烟花闪光折算成调色强度，不额外铺满屏 |
| **贴图化** | 雨丝、光晕、火星用预渲染贴图按颜色缓存；远处细雨按亮度合批成一条路径 |
| **无 GC 抖动** | 粒子删除用交换删除（O(1)），不在循环里 splice |
| **后台即停** | 切到后台时 rAF 停止、视频暂停；回到前台不会出现巨大的时间步长 |

实测（无头 Chromium、纯 CPU 软件光栅，比真机 GPU 慢很多，只用于相对比较），一次完整大笑序列里特效部分的每帧耗时：

`tools/bench.mjs`：540×960 / q0.5 平均约 7.5 ms；720×1280 / q0.75 平均约 27 ms；1080×1920 / q1 平均约 72 ms（只给桌面高档用）。

## 4. 边界情况

| 情况 | 处理 |
|---|---|
| 非 https / 不支持 getUserMedia | 明确提示；微信、QQ、微博、抖音等内置浏览器提示「在浏览器打开」 |
| 拒绝授权 / 没有摄像头 / 摄像头被占用 / 约束不满足 | 分别给出原因；约束失败自动降级重试（1280×720 → 任意分辨率 → 任意摄像头） |
| 摄像头中途断开 / 拿到摄像头但视频播放失败 | 立即释放视频轨道，回到首页并提示 |
| 模型加载失败或超过 30 秒 | 进入手动模式：点屏幕、空格或「哈！」触发，雨保持下着 |
| GPU 推理失败 | 自动回退 CPU 推理 |
| 人像分割不可用 | 用脸框估算头肩轮廓，雨照样落在头上 |
| 画面里没有脸 | 1.5 秒后雨停，并提示把脸放进画面 |
| 多人 | 跟随最大（最近）的脸；人像分割包含所有人，雨会落在每个人身上 |
| 脸太小（太远） | 脸宽小于画面 5% 时不做表情判定，避免误触发 |
| 每个人的嘴型天生不同 | 个人基线：只看相对自己放松时的变化 |
| 说话、打哈欠、只微笑 | 不触发（要同时微笑和张嘴） |
| 连续大笑 | 一次烟花放完后冷却 1 秒 |
| 头在画面很高、上方没有天空 | 烟花自动排到两侧更低的位置并缩小 |
| 横屏或竖屏摄像头、任意分辨率 | 统一裁成 9:16，构图跟着人脸走 |
| 视频比烟花短 | 定格最后一帧，等烟花放完再结束导出 |
| 录制中点停止，但烟花还没放完 | 等放完再停 |
| 视频加载或模型预热期间点返回 | 取消该次异步任务，不会在后台继续播放或录制 |
| 录制中点返回 | 丢弃本次临时录制并释放资源，不会被导出完成页反弹回来 |
| 系统设置了减少动态效果 | 粒子量降到 60% |
| 浏览器不支持录制 | 隐藏录制按钮，提示改用系统录屏 |

## 5. 以后改视觉

- 换颜色、大小、雨量、烟花种类与出场顺序、调色、文案：**只改 `src/theme.js`**。识别、物理、性能分档都不读其中的数值以外的东西，改它不会影响交互。
- 换画法（比如把雨换成花瓣贴图）：改 `effect-chain.js` 里的 `_sprite()` 和对应的 `_draw*()`。物理与碰撞在 `update()` / `_debris()`，和画法分开。
- 改完后跑一遍：`node tools/test-controller.mjs`（判定逻辑）和 `node tools/bench.mjs`（性能）。

## 6. 网址参数

`?tier=high|mid|low` 强制档位 · `?th=0.42` 触发阈值（默认 0.42，越小越容易）· `?hud=0` 隐藏界面 · `?mode=demo` 直接演示 · `?debug=1` 显示档位、帧率、识别耗时、表情数值、粒子数。

## 7. 本地开发与离线工具

```bash
bash scripts/fetch-vendor.sh && python3 -m http.server 8080      # 打开 http://localhost:8080
node tools/test-controller.mjs                                    # 笑声判定：9 种合成表情
node tools/bench.mjs                                              # 特效每帧耗时（需要 playwright）
node tools/ci-verify.mjs tests/fixtures/laugh.webm out            # 真实模型端到端验收
```

离线渲染任意视频（逐帧精确，视频不够长自动定格）：`tools/analyze_clip.py`（MediaPipe 人脸检测、FaceMesh、人像分割，通过 OpenCV DNN 运行）→ `tools/build-track.mjs`（同一个笑声判定器）→ `tools/render-demo.mjs` → `tools/events_to_audio.py`。

> `tests/fixtures/laugh.webm` 是测试用实拍（含人脸）。公开仓库前可以换成你愿意公开的片段。
